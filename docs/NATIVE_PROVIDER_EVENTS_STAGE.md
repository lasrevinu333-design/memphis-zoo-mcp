## Finite original observations, not notification effects

Only received/displayed/opened/acknowledged exist on this server receipt surface. Dismiss is local-only. Each item binds its event UUID, SHA256 record ID derived from original generation/job/key, full reduced recipient/assignment/principal/token/content fields, original observation and admitted_at to an existing immutable LOCATIONv2 reservation. No generic widened kind parser, relabeling to a successor generation, provider-acceptance substitution, reminder-clock reset or fabricated device event.

Current active employee/device/assignment and confirmed unrevoked unexpired credential are checked under existing publication→device→credential→employee→registration→generation→job→reservation lock order. Original same-principal reservations at or before retirement can drain after payload expiry/token rotation; revoked or reassigned identities cannot, including exact receipt replay. Receipt admission deliberately does not require a current delivery-worker lease or current business projection after the original observation; it is historical observation storage, not renewed display authority.

One received transition precedes other actions in stored evidence; batch processing orders received first even if its input enumeration was later. Original admitted_at must lie within reservation validity and is identical across actions. Received retains even a null original observation from quarantine. Displayed requires a claimed authenticated observation within payload validity; Open/ack may be offline/historical with null observation time and never synthesize displayed. Known time and same-boot elapsed chronology cannot precede admitted/received evidence; boot reversal is rejected. The server records an authenticated device claim, not an independent physical-display proof or a newly qualified clock.

`employee_native_provider_events` is append-only with unique event UUID and unique record/action. Changed original observation or new UUID for the same finite transition conflicts. Exact response-loss replay returns the same original event and server_received_at with replayed=true. Missing/rejected batch entries remain pending; a valid item in a mixed batch can settle independently. Repeating retained original events is the readback mechanism; it NEVER sends another notification. The private request ledger binds each HMAC nonce to its credential, body digest and attestation digest; changed reuse conflicts. No caller-provided SQL test time is exposed.

Native `pendingEvents` selects pending received transitions first, then other actions, using stable event-ID order within each group and the existing1536 stored-event/16 request-item limits. Selection performs no writes or ID changes; settled evidence remains retained. The >16 deterministic encrypted-journal regression covers restart,16+16+8 draining and unchanged original events.

New tables are RPC-only FORCE RLS, direct access revoked even to service_role. Only the public wrapper has service-role EXECUTE. Private shape/time/transaction helpers are denied to all runtime roles.
