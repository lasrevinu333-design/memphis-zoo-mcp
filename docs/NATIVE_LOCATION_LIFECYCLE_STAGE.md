# Guarded LOCATION lifecycle contract

Source prerequisite only. Production `index.js` does not install these native routes; no employee sender, native factory or manifest is activated. QP-01 remains unqualified/SUSPENDED. This is neither closed-app delivery nor whole-system notification completion.

## Callable owners

- `custodial_native_location_target(uuid,uuid)` / `resolveNativeLocationTarget`: service-only job+lease lookup. Returns current eight-field original recipient/generation/registration/token-digest snapshot and the internal token. Snapshot is not dispatch authorization. `custodial_native_location_reserve` must recheck it under locks before a single attempt. Never log/return the token to an employee endpoint or diagnostics.
- `custodial_native_location_outcome(jsonb,jsonb)` / `recordNativeLocationOutcome`: service-only exact original reservation binding plus caller-persisted operation UUID and finite provider evidence. The binding includes job, original lease, registration, generation, principal/token/content hashes, reservation timestamp and original credential/employee/device/epoch. Provider acceptance, known nonacceptance and unknown outcome are distinct. Exact lost-response retry returns the committed original result; changed operation payload or contradictory terminal outcome conflicts. Evidence is append-only; no original row or successor registration health is rewritten.
- `custodial_native_location_outcome_status(jsonb)` / `readNativeLocationOutcome`: service-only exact original binding readback, even after business expiry/rotation. Prepared/unknown is not accepted; accepted is not device received/displayed. Status never authorizes a send. Reservation replay now refuses an already final outcome rather than relabelling it unknown.
- `custodial_native_location_inventory(uuid,text,uuid,text,jsonb)`: invoked only by the existing exact native raw-body/HMAC/current-credential `POST /employee-notifications-api/native-provider/inventory` route owner. The module remains unmounted in production. Events remains503. The separate clock-qualified native effect owner is not supplied by this HTTP result.

Private `_at` helpers accept synthetic test time only for disposable postgres tests. All seven runtime roles, including service_role, are denied those helpers. Public wrappers accept no caller timestamp. Live time is sampled after owning locks; no `Date` conversion of SQL microseconds. New private tables are FORCE RLS with no direct runtime grants, including service_role, and ALWAYS immutable evidence triggers. Exact recovery metadata is captured; root owns the final combined canary.

## Inventory semantics

The request/response is the existing exact native inventory v1 protocol, restricted to new LOCATION v2 reservations. It contains no provider token or full installation seal. Full current authenticated credential/device/employee/epoch and stored native principal digest/generation bindings are mandatory on every page. Same-principal retired generations may recover only original reservations at/before retirement, never revoked/foreign generations. Current owner/revision/projection/source/verified-visit/acknowledgement/expiry remains checked through the shared LOCATION business predicate. The leased-send guard stays intact; recovery does not require an expired worker lease.

Each scan freezes server time, a `(reservation_at,job_id)` ceiling and the exact candidate job IDs. New arrivals cannot enter an old scan even if they sort below its ceiling. Pages return at most32 current rows, strictly after the requested cursor, and advance only to the last returned row. Current-filter invalidation excludes that stale row but does not skip remaining valid older candidates. Missing/mismatched cursor windows get the exact authenticated409 restart envelope; native preserves recovery need until its own explicit completion/readback. Initial response loss retries the same frozen scan. A subsequent scan recovers new arrivals. Inventory neither resends FCM nor creates received/displayed/acknowledged events by itself.

Rows remain the exact immutable payload bytes/hashes; canonical LOCATION schema and current principal are validated again by the native decoder/journal. Each response is capped at256KiB. Server snapshot capacity4096 is a fail-closed pending error, not a truncated scan or a new business timeout. Known nonacceptance is excluded; prepared/unknown/provider-accepted remains eligible only while current. No historical lineage is fabricated.

## Remaining integration gates

The production sender still uses legacy helpers and must be deliberately switched to this target→reserve→single data-only attempt→exact outcome/readback route after required review/qualification. It must durably retain original binding and outcome operation evidence. Known nonacceptance is terminal/no-resend in this bounded source; any future authorized attempt-retry policy needs new immutable attempt identity, never deletion/relabeling of this reservation. Registration-health updates must be exact-generation/current-token gated if added; this stage does not mutate health.

Authenticated device event receipts remain unimplemented. Native production owner construction, removal fencing, qualified clock/current effect admission, in-app claim/audio integration, lunch canonical lifecycle and other required Event/Messenger/9:45 kinds remain explicit capabilities to complete. Later artifact/device acceptance remains at its proper post-build phase; absence of these source capabilities is not renamed a future physical test.
