# Owner-approved manual planning data

`packet/` preserves all eight source JSONs and the original handoff, unresolved-policy, manifest and checksum files unchanged. `catalog.json` records their issued identity and exact current-field selection. Historical rejected alternatives remain provenance; the adapter does not adopt them.

`src/approved-manual-week.js` reads this data with the maintained schedule date and PostgreSQL JSONB digest helpers. It provides the seven fixed bases,40 full-hour reliefs, exact scheduled-departure transfers and held planning previews. Each combined group receives its single1–10 rating; these are not physical minutes or replacements for the retained component-weight ledger. Thursday and Friday end at16:00. Inherited duties mean radio/restroom alerts and issues, not mandatory additional cleaning routes.

Example internal preparation, using a new output path:

```sh
node scripts/prepare-approved-manual-week.mjs --output /absolute/private/manual-week-preview.json --day friday --time 15:00
```

A custom packet requires both `--catalog` and its independently issued `--manifest-sha256`. The command writes data only. It cannot register sources, publish, migrate, deploy or create a compiler/phone acceptance receipt.

The output also includes `compilerData` from `src/approved-manual-compiler-data.js`:346 ownership fragments using native assignment field names,40 static shift/lunch availability inputs, the maintained compiler's validated40-loan full-hour policy and the exact closing-owner maps. Adjacent windows merge only when the same employee keeps the same group. The separate23-group rating authority does not multiply ratings by restroom member or segment count. No optimizer runs.

These fragments still require canonical eligibility/capacity hydration, an approved effective date and live roster readback, and adaptation of the existing engine to the new rating authority. They deliberately contain no canonical compiler input, source registration or acceptance receipt. The approved manual data remains the fixed mapping; source preparation cannot choose a new owner.

`reference-bindings.json` links the eight exact approved employee names and all23 combined groups to the retained candidate's employee, slot and parent-location UUIDs. The reader checks its digest, the exact retained registration bytes, each physical member list and each service mode. Education keeps its explicitly approved four-classroom umbrella definition; no classroom UUIDs are invented. These are candidate references, not a live roster readback or a registered Source. The old reference incumbency dates do not select this packet's publication date.

Activation remains held for prearrival ownership, non-Monday09:45 policy and weekly Elephant Trunk restroom duty. The exact75/25 formula and an effective publication Monday are not invented. Elephant Trunk stays explicitly unresolved with no assigned owner or score. Prearrival previews refuse to fabricate ownership; staffed-end previews have no fictional closer. This is a separate dataset: the retained eight-employee and ninth-position source files are unchanged.

The maintained approved-template/dated staffing engine still requires adaptation and qualification for this packet. Its existing count-selected approved-pattern requirement is not satisfied merely by loading these seven daily plans. No normal absence recalculation, active website/phone use or physical acceptance is claimed by this data adapter.
